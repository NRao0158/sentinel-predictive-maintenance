# Model card

## Task and intended use

Educational predictive maintenance on FD001: binary failure risk within 30 cycles and capped remaining useful life. Demonstrates preprocessing, leakage prevention, evaluation, model serving, and operational workflow. Do not apply the engine model to other device types.

## Dataset and provenance

NASA Ames PCoE C-MAPSS FD001; one operating condition and one fault mode (high-pressure compressor degradation), 100 training trajectories and 100 truncated test trajectories, 21 sensors and 3 settings. Generated by simulation, not measurements from a logistics facility. NASA source links to the PHM Society S3 mirror used by the download script. Source attribution: Saxena & Goebel (2008); Saxena, Goebel, Simon & Eklund, *Damage Propagation Modeling for Aircraft Engine Run-to-Failure Simulation*, PHM08. The NASA catalog does not provide an explicit dataset license; do not imply the code license covers source data. Review source terms before broader redistribution. Only a compact demo sample is bundled; full raw files are ignored by Git.

## Features and labels

Cycle count and 14 varying FD001 sensor channels, with trailing 10-observation mean and difference from 10 observations earlier. Early deltas are zero until enough history exists. Rolling transforms are performed separately for each engine in ascending cycle order. No future observations contribute to inference. Full trajectories construct training targets only: max cycle minus current cycle. Test RUL is remaining observed history plus official per-engine RUL offset. Class label: RUL <=30, with terminal failure rows excluded in training/internal evaluation. Operational cycles must not be converted into hours without a verified mapping.

## Experiment design

Seed 42 machine split: 60 fit, 20 validation, 20 internal audit. Machine IDs are stored in metrics. Three classifiers compared by validation PR-AUC. Two regressors compared by validation MAE. No test-driven model selection or retraining after selection. Official test evaluated once at last observation per engine; audit metrics cover all nonterminal cycles and are not directly comparable to the official test distribution. Long audit trajectories receive more observation weight. Bootstrap interval resamples audit engines, accounting for within-engine correlation, but covers only one split and excludes model-selection uncertainty.

PR-AUC emphasizes rare positive ranking; precision/recall summarize the validation-selected threshold; Brier measures probability error. Scores are not calibrated, and a displayed percentage is not a validated frequency. RUL target cap=125; reported MAE/RMSE use the same cap. Validation absolute residual 90th percentile forms a heuristic interval, not a calibrated prediction interval. Independent local feature perturbations are sensitivity estimates, not causal explanations or SHAP values. Global permutation importance uses validation data.

## Limitations

- FD001 is comparatively simple; no multi-condition FD002/FD004 generalization is demonstrated.
- No printer/scanner labels, abrupt network faults, supplies, maintenance records, or recovery measurements.
- No real-time collection, fault-type classifier, calibrated probabilities, or automatic retraining.
- No measured outage reduction, package throughput improvements, dollar savings, or facility pilot.
- Range checks flag some unusual inputs but do not establish drift or guarantee reliability.
- Alert history is session-local and disappears on restart; manual replay can move time backward.
- Model deserialization must use only the trusted bundled artifact; never load uploaded joblib files.

## Next steps

Collect approved longitudinal device telemetry and timestamped incident labels; define an actionable horizon in minutes; obtain device/maintenance metadata; use device-disjoint and forward-time evaluation. Build a separate domain model rather than renaming engine sensors as printer measurements. Add calibration and unit-grouped model selection, FD002 robustness tests, persistent event storage, and incident-level lead-time/cost evaluation before any live pilot. Retraining should require evaluated candidate promotion and rollback; current training is a manual reproducible command.
